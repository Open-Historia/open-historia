# Subscription agents answer through the game, and only the player starts them

Players want to play on the subscription they already pay for (Claude Pro/Max, ChatGPT Plus/Pro, Google AI Pro) instead of an API key, and free Gemini keys are running out sooner and are busier than they were. API keys stay the primary way to play; this adds a second way on desktop.

An **Agent Connection** is a new kind of Connection. It sits in the Fallback list like any other, but nothing is sent to a provider from the browser: the game puts the request it built into the **Agent queue** on the local server and waits for an **Agent** to answer it. The game then checks and applies the answer exactly as it applies one from an API, so validation, salvage, the application receipt, rollback snapshots and the staged reveal all still run. **The agent never writes the save.** `world.json` and its siblings are written by the game alone.

An Agent Connection answers only what the **player starts**: a time skip and what the game does right after it, an advisor message, a reply to the player's own diplomatic message, a Game Master command, an interactive event's choice. What the game starts by itself (background diplomacy and outreach, idle chats, automatic stat tracking) never goes to it: nobody is at the terminal.

There is one way an Agent Connection is answered, the same for every subscription: the player plays in the game as they always do, opens their own Claude Code, Codex or Antigravity CLI in the **Agent folder**, and types `/answer` (or `/skip`, the same command under its first name) when the game shows something waiting. One `/answer` answers everything the player started that is waiting, then stops. The folder carries the instructions (`AGENTS.md`, with `CLAUDE.md` importing it), the `/answer` skill and the settings for the game's MCP server, which lists, reads and answers the queue. The agent hands each request to a fresh sub-agent, which reads the prompt from a file and writes the answer back. Claude Code does this today; whether Codex and Antigravity CLI do it the same way is checked when the folder is built, and an Agent without sub-agents answers in its own session.

This is recorded because it draws a line other features will be tempted to cross: **the game never starts an Agent (`claude`, `codex`, `agy`), never reads its credentials, never turns a subscription into an endpoint the game calls, and never documents a way for an Agent to pick requests up by itself.** Crossing it is what gets players' accounts suspended.

## The terms this follows (checked October 2026)

- **Anthropic** does not permit third-party developers "to route requests through Free, Pro, or Max plan credentials on behalf of their users", and has enforced this since April 2026. It does not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription". (`code.claude.com/docs/en/legal-and-compliance`)
- **Google** stopped serving Gemini CLI for consumer tiers on 2026-06-18 and moved them to Antigravity. It permanently suspended AI Pro and Ultra accounts whose sign-in was used by third-party tools, without refunds, and its Antigravity FAQ treats accessing the service through third-party software as a violation that can end the account. (`antigravity.google/docs/faq/`)
- **OpenAI** has publicly welcomed players using their ChatGPT account in open-source tools they sign in to themselves (Tibo Sottiaux on X; the Codex for Open Source page). It also said in August 2026 that "converting a subscription into api traffic" is unsupported and flagged by its fraud checks, and its Terms of Use forbid any "automated or programmatic method to extract data or Output" outside the API. None of the welcome is contractual. Since then it has opened Sign in with ChatGPT, through which an open-source app may request a client ID and spend the player's ChatGPT plan on Responses API requests (`developers.openai.com/siwc/quickstart`). That is a sanctioned route this ADR does not take; it would be a Connection of its own.

These change. Check all three before each release that touches this.

## Considered Options

- **The agent edits the save files directly.** Rejected. The turn's rules live in the browser (`gameplay.js`); an agent would have to reimplement them, `saveGame` writes `world` whole and would overwrite the agent's edit or be overwritten by it, the running game sees an outside edit only on the 60-second backstop (`runtimeStore.js`), and the web and Android builds have no files at all.
- **A headless bridge: the local server runs `claude -p`, `codex exec` or `agy -p` for each request and offers it to the game as an "OpenAI Compatible" endpoint, so the time-skip button works as with a key.** Rejected for every provider. For Claude and Gemini it is the game routing requests through the player's subscription on their behalf, which Anthropic's terms forbid and Google suspended accounts for. For Codex it was first chosen, as OpenAI is the most open of the three, then dropped: it turns a subscription into API traffic, the pattern OpenAI says its fraud checks flag, and it extracts Output programmatically outside the API. One player pressing the button does not change what the traffic looks like.
- **Automatic pickup through a Claude Code channel, `/loop`, or any Agent's scheduler.** Rejected for now. It turns the player's Agent into the game's inference backend, which is a grey area under all three providers' terms. Custom channels are also a research preview that needs `--dangerously-load-development-channels`.
- **Time out and fall through to the next entry.** Rejected. The player put the agent there to avoid spending their API allowance; a skip that quietly moves to Gemini after a few minutes spends it anyway. An Agent Connection waits until it is answered, the player cancels, or the player sends it on with **Use API key**; cancelling cancels the call, not the entry.
- **A command per chat, or the chat typed in the terminal (`/advisor …`).** Not now. The game's own chat windows stay the one place the player talks, and one `/answer` answers whatever is waiting. Chatting from the terminal may come later as an extra.
- **Streaming an Agent's reply word by word.** Rejected for now. An Agent hands its answer over in one tool call, once it is written; sending it in pieces costs it a step per piece and slows the reply. The game shows that the Agent is writing until the reply lands.
- **A separate "agent mode" switch outside the Fallback list.** Rejected, per ADR 0002: the list is the only place that decides who answers a call.
- **Hand the prompt over in the MCP tool's result.** Rejected. A time skip is about 47,000 tokens and Claude Code caps an MCP result at 25,000 by default, so the prompt is a file in the Agent folder and the tool returns its path.

## Consequences

- An Agent Connection names the kinds of request it answers, as ticks on its entry in Settings: time skips (`SKIP_SPENDERS` in `requestBudget.js`, with the follow-ups the game asks right after a skip, such as a first stat-sheet reading), the advisor, diplomacy, the Game Master and interactive events. All are ticked when the Connection is added. Anything unticked, and everything the game starts by itself, is passed over without a request, a mark or a notice (the runner's `serves(entry)`) and goes to the entry below. Settings → per-task models works as it does for any entry.
- Background AI does not use an Agent Connection. Nobody is at the terminal to answer it. With nothing below the Agent, those requests do not run, and the Agent's Settings help says so.
- Everything waiting on the Agent shows "Waiting for your agent: type /answer" where it was asked (the skip's progress row, under the player's chat message), with **Open the Agent folder**, **Cancel**, and **Use API key** when there is an entry below. Use API key sends that request on to the next entry; on a time skip it sends the rest of that skip, so its follow-ups do not stop and wait again. It is the player's click, never a time-out.
- A **pause** switch on the Agent entry sends everything to the entries below until it is switched back, for a player away from the terminal.
- Waiting on an agent is not a failure: it leaves no Busy, Rate limited or Spent mark, and it never ends by itself.
- Desktop only. The queue lives on the local server, so the web build and the Android app do not offer the Connection kind.
- The queue is in memory. A reload drops what is waiting, as it drops a skip waiting on an API.
- Each request is answered by a fresh sub-agent, so the player's own session grows by a few lines per answer rather than by the prompt. The player does not need a new session per skip or chat, and `/clear` loses nothing, since the game holds the state.
- One `/answer` answers everything the player started that is waiting, oldest first: several chat messages, and a whole time skip. A skip asks its requests one after another (the review, history and stat sheets are written from the jump's result, and its follow-ups come after it lands), so the game cannot hand them over at once. While a skip runs, `/answer` asks the game for the skip's next request and waits for it, until the game says the skip and its follow-ups are finished; then it stops. A broken answer comes back as a retry within the same `/answer`.
- `/answer` with nothing in the Agent queue tells the player "Nothing is waiting" and stops. It never waits for anything the player has not started, and never keeps watching after what it answered ends: either would be the first step of an Agent that picks requests up by itself.
- A reply from an Agent arrives whole; the game says the Agent is writing until it lands.
- The MCP server is served by the game's local server over localhost, so the player installs nothing beyond their own Agent. The port can change between launches, so the game writes the current address into the Agent folder each time it starts.
- The game writes a random token into the Agent folder each time it starts and accepts an answer only when it carries that token, so no other program on the machine can answer a request.
- An Agent calls the task's lookup functions as a tool of the game's MCP server while it answers, and the game answers them from the running page: a skip's, and the advisor's and the chats' own. They follow the player's lookup setting, as for an API entry, but none of them is a request: the skip spends no `jumpLookup` rounds on an Agent.
- The Agent folder lives in the player's saves folder, so updates do not remove it. The game rewrites its instructions, `/answer` skill and MCP settings each time it starts, so a game update updates the Agent's prompt too. A request's prompt file is deleted once it is answered or cancelled, and any left over are deleted when the game starts.
- Single player only. Shared games, and OpenAI's Sign in with ChatGPT for open-source apps, are separate later pieces.
- The models are the player's, chosen inside their own Agent, never in the game. The first `/answer` (and `/answer models`) asks the player which model writes the skip (the jump and the history), which does the quick checks after it (the turn review, stat sheets, institution ballots), and which writes chat replies (the advisor, diplomacy, the Game Master, interactive events; the quick model unless the player names another), and saves the answer in the Agent folder's `models.json`, the player's own file, which the game never writes. That choice is for Open Historia only, so the player's general rules elsewhere stay as they are, and it comes before them here. In Claude Code the game writes it into the `skip-writer`, `skip-quick` and `chat-writer` sub-agents' definitions, a setting rather than an instruction, which a session reads when it starts; `/answer` also starts each sub-agent on it, so the session that asked uses it too; another Agent is asked to start each sub-agent on that model where it can. A role with no model named inherits the player's session, effort included. The game offers no model setting of its own.
