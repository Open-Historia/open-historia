## Understanding Our Patch Notes

Updates are generally divided into the following categories:

- **New** - Features and functionality added to the game.
- **Changed** - Improvements or adjustments to existing functionality.
- **Fixed** - Bugs and unintended behavior that have been corrected.
- **Performance** - Optimizations affecting speed, resource usage, or stability.
- **Known Issues** - Problems that remain unresolved or require additional investigation.

Not every update contains every category. Smaller releases may consist entirely of bug fixes.

Each update identifies the platforms and release channels to which it applies.

## Reporting Problems

Found a bug or unexpected behavior after an update?

Please report it through [GitHub Issues](https://github.com/Open-Historia/open-historia/issues) or our [Discord community](https://discord.gg/jJYr3sh9ku).

When possible, include the affected version, scenario, reproduction steps, screenshots, logs, or save files.

Your feedback helps us identify regressions and improve OpenHistoria.

## For Developers and Release Maintainers

This archive is maintained on the repository's `main` branch, including documentation for Beta releases.

Each publicly announced update should receive a permanent Markdown file in this directory.

**File naming convention:**

`YYYY-MM-DD-channel-short-description.md`

Example: `2026-10-10-beta-bugfixes.md`

Each entry should include:

- Release date and affected channels/platforms.
- Release title and summary.
- Confirmed changes and bug fixes.
- Known issues or important upgrade instructions, where applicable.
- The relevant build identifier or source commit.
- A link to the corresponding GitHub download release.

Add each new entry to the **Update Archive** section above, newest first.

If multiple updates share a date and channel, use distinct descriptive filenames.

**Important:** GitHub's rolling download releases are continuously updated. This archive preserves the historical patch notes for individual releases and must not be overwritten when a newer build is published.

Only document changes that were actually included in the published build.
