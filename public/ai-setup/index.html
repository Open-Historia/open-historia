Open Historia / AI Setup Guide

Connect your AI

Open Historia's world is simulated by a language model you supply — from a free Gemini key to a model running on your own hardware. This guide covers every option.

What the AI Does in Open Historia

Time skips — resolves your actions, plays every other nation, writes the events, moves borders and fronts
Diplomacy — leaders answer you in character in natural-language chat
Advisor — situation summaries, economic analysis, and war planning
Intelligence — briefings on any nation, and what your spies intercept

This is not optional. There is no scripted simulation underneath: without a connected provider you can look at the map and use the map editor, but time cannot advance and nobody will answer your messages.

How It Works

Open Historia supports five provider types from a single settings panel, and you can switch between them at any time:

  • Gemini — Google's native API (Google AI Studio); the default
  • OpenAI — the official OpenAI API
  • Anthropic — Claude via the Messages API
  • OpenAI Compatible — anything that speaks the /v1/chat/completions protocol: Ollama, LM Studio, llama.cpp, vLLM, DeepSeek, Groq, Together, OpenRouter, and more
  • Anthropic Compatible — a self-hosted proxy or gateway that speaks the Anthropic Messages API

Your key is stored in the app and sent only to the provider you chose — Open Historia has no server of its own in the loop. Requests go straight from the game to the provider. In the desktop app and on a self-hosted install, a provider that refuses browser requests (local servers such as llama.cpp and LM Studio usually send no CORS headers) is automatically reached through the game server's own same-origin relay instead, so those just work. On openhistoria.com there is no relay: the provider must accept requests from the website. Cloud APIs do; a local Ollama needs to be told to allow the site's origin (see Ollama below).

To configure a provider: open a game, open Settings, and under AI pick the provider and fill in its fields.

Provider Setup Options

Google Gemini (Default — Free Key Available)

Gemini is the default provider and the quickest way to get started. Google AI Studio issues keys with a free usage tier that is enough to try the game.

Get an API key

Go to Google AI Studio, sign in with a Google account, and click "Create API key".

Configure in Open Historia

In Settings, select Gemini and paste your key. No endpoint URL is needed. The default model is gemini-3.5-flash-lite; you can enter any Gemini model id your key can use — a larger Flash or Pro model gives stronger reasoning at a higher cost and tighter rate limits.

OpenAI

Use OpenAI's API with a paid API account.

Get an API key

Sign up at platform.openai.com, add a payment method, and create a key under "API keys".

Configure in Open Historia

Select OpenAI and paste your key. The endpoint is fixed. Leave the model blank and the game picks from the models your key can access, or type a specific model id.

Anthropic Claude

Use Anthropic's Claude via the Messages API — strong instruction-following and writing, which shows in diplomacy and event narration.

Get an API key

Sign up at console.anthropic.com and generate a key.

Configure in Open Historia

Select Anthropic and paste your key. The default model is claude-haiku-4-5, the fast and inexpensive option; enter a Sonnet model id for richer writing at a higher cost.

DeepSeek

DeepSeek offers capable models at low cost. Its API is OpenAI-compatible, so it works through the OpenAI Compatible provider.

Get an API key

Register at platform.deepseek.com, add credit, and create a key.

Configure in Open Historia

Select OpenAI Compatible. Set the endpoint to https://api.deepseek.com/v1, enter your key, and set the model to deepseek-chat (or deepseek-reasoner for a reasoning model).

Local Models (Free & Private)

Run a model entirely on your own hardware: no API key, no internet after the download, and nothing leaves your machine. Use the OpenAI Compatible provider and point it at your local server.

What the game needs from a local model. A time skip sends the model a large description of the world — on a mature save it runs to tens of thousands of tokens — and expects a long, precisely structured JSON answer back. Pick a model that follows instructions well, and run it with a large context window (32k tokens or more; the default context of many local setups is far smaller and the request will be refused as too long). Small models of around 3B parameters usually cannot complete a time skip; mid-sized instruct models (roughly 7B–14B and up) are the practical floor, and larger is better. Diplomacy chat and the advisor are far less demanding.

Ollama (Easiest Setup)

Ollama is the simplest way to run models locally on Windows, macOS, and Linux.

Install Ollama and pull a model

Download from ollama.com, install, then pull an instruct model of your choice with ollama pull <model>. Raise its context window — for example by setting OLLAMA_CONTEXT_LENGTH=32768 before starting Ollama, or with a num_ctx parameter in the model's settings.

Configure in Open Historia

Select OpenAI Compatible. The endpoint defaults to http://localhost:11434/v1, which is Ollama's. Enter the model name you pulled; no API key is needed.

Playing on openhistoria.com?

The website's requests come from a different origin, and Ollama refuses those unless told otherwise. Start Ollama with OLLAMA_ORIGINS=https://openhistoria.com. The desktop app needs no such setup.

LM Studio (GUI)

LM Studio provides a graphical interface for downloading and running models.

Download a model and start the server

Use the built-in model browser to download an instruct model, load it with a large context length, then start the local server from the Developer tab. The default address is http://localhost:1234/v1.

Configure in Open Historia

Select OpenAI Compatible, set the endpoint to http://localhost:1234/v1, and enter the model name shown by LM Studio. No API key needed.

llama.cpp (Maximum Control)

llama.cpp runs GGUF-format models with minimal overhead and is the most configurable option for technical users.

Start the server with a large context

./llama-server -m model.gguf -c 32768 --port 8080

Configure in Open Historia

Select OpenAI Compatible and set the endpoint to http://localhost:8080/v1.

Other Cloud APIs (OpenAI-Compatible)

Any cloud service that speaks the OpenAI chat completions protocol works through the OpenAI Compatible provider. Common endpoints:

Service Endpoint URL Notes
Groq https://api.groq.com/openai/v1 Very fast inference of open-weight models
OpenRouter https://openrouter.ai/api/v1 Many providers' models behind one key; use the full model slug
Together https://api.together.xyz/v1 Wide selection of open-weight models
DeepInfra https://api.deepinfra.com/v1/openai Open-weight models, pay per token
Fireworks https://api.fireworks.ai/inference/v1 Fast serverless inference

For any of these, select OpenAI Compatible, paste the endpoint URL and the key from that service, and set the model name exactly as the service lists it.

Choosing the Right Option

Provider Cost Privacy Best For
Gemini Free tier, then pay per token Cloud Quickest setup, the default
OpenAI Pay per token Cloud Strong all-round quality
Anthropic Claude Pay per token Cloud Rich narrative and diplomacy
DeepSeek Low cost per token Cloud Budget-friendly quality
Ollama / LM Studio / llama.cpp Free Fully local Privacy and offline play; needs a capable machine
Groq / Together / OpenRouter Varies by service and model Cloud Fast inference, many models

Rule of thumb: the quality of your game is the quality of the model. A free Gemini key is the best starting point; move up when you want deeper reasoning and richer writing, or go local when privacy matters and your hardware can carry a mid-sized model with a large context.

Troubleshooting

A time skip fails immediately, or nobody answers in chat

The provider is not set up or not reachable. Check that a provider is selected in Settings, that the key is valid and has credit, and — for local backends — that the server is running and the endpoint URL matches, including the /v1 path.

"Context window exceeded" or "request too long"

The model's context is too small for the time-skip request. Run the local model with a larger context window (see above) or choose a model with more context; on cloud providers, pick a model with a larger window.

API key not working

Check that the key matches the selected provider — a Gemini key does not work with the OpenAI provider and vice versa. For OpenAI-compatible services, the model name must be exactly what the service expects (for example deepseek-chat on DeepSeek, or the full slug such as openai/gpt-4.1 on OpenRouter).

Responses are slow

A time skip is a long generation and takes a while even on fast cloud models. For local models, enable GPU offloading (Ollama and LM Studio both support it) or try a smaller model. Groq is particularly fast among cloud services.

CORS or "failed to fetch" errors

In the desktop app and on a self-hosted install, providers that refuse browser requests are relayed through the game server automatically. On openhistoria.com there is no relay: a local Ollama must be started with OLLAMA_ORIGINS=https://openhistoria.com, and servers that never send CORS headers (llama.cpp, LM Studio) cannot be used from the website at all — use the desktop app for those.
