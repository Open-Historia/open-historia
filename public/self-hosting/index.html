Self-Hosting Open Historia

Run the game server yourself — from source on any machine with Node.js, on your own network, or entirely offline with a local model.

Do You Need This?

Probably not. The desktop app already runs the whole game — server included — on your own machine, with nothing else to install. Self-hosting from source is for when you want to:

  • Run it on a machine without a desktop: a home server, a NAS, a Raspberry Pi, or a phone with Termux.
  • Play from other devices: open your saves from a laptop, tablet, or phone browser on the same network.
  • Hack on it: the source is AGPL-3.0-licensed; this is how you run your own changes.

Whichever way you run it, Open Historia is local-first: there is no central game server and no account. Your saves and scenarios live in the server's data directory on your machine, and your AI key goes only to the provider you configured.

Install and Run from Source

Step 1 — Prerequisites

Git and Node.js 22 LTS or newer (20.19 is the minimum for the server and the client build).

Step 2 — Clone, fetch the map data, build 
git clone https://github.com/Open-Historia/open-historia.git
cd open-historia
node scripts/fetch-map-assets.mjs   # downloads the world map data (about 275 MB)
npm install
npm run build

On a server-only box (Termux, a NAS, anything headless) use npm install --omit=dev --omit=optional instead of npm install: it skips Electron and the desktop build chain, which are not needed to run the server.

Step 3 — Start the server 
node server/server.js

Then open http://localhost:3000 in a browser. Set PORT to use another port. All state — saves, scenarios, editor documents, uploaded flags and basemaps — is plain files under server/data/ (or wherever OH_DATA_DIR points); back that directory up and you have backed up everything.

Playing from Other Devices

Any device on your network can play by opening the server's address in a browser — http://192.168.x.x:3000, using the server machine's local IP. The game loads from the server itself, so no extra configuration is needed on the client side. Everyone who connects sees and plays the same library of saves; there is no multiplayer mode and no accounts.

Whether the server answers other devices at all depends on the build:

  • Current stable release: the server listens on every network interface as soon as it starts, so other devices can connect right away.
  • Newer builds (the beta, and the source on the beta branch): the server answers only the machine it runs on until you turn on Settings → Network → "Let other devices connect". It takes effect immediately, is remembered, and shows you the exact address to type on the other device. On a headless box, set OH_HOST=0.0.0.0 instead (or one interface's address); that overrides the switch.

The game's API has no password. While the server is reachable from the network, anyone on it can read, change, and delete your games and scenarios — fine on a home network you control, a bad idea on café, hotel, dorm, or office Wi-Fi. For remote play across the internet, put the machines on a private network with a tool such as Tailscale or ZeroTier rather than forwarding the port on your router.

The Android app does not connect to a self-hosted server: it is the browser version packaged as an app, streaming the map from the community content nodes with its games on the phone. A phone plays your self-hosted saves through its browser instead.

Environment Variables

Variable Default What it does
PORT 3000 The port the server listens on.
OH_DATA_DIR server/data Where saves, scenarios, and everything else is stored.
OH_HOST unset Newer builds: which interface to listen on. 0.0.0.0 means every device on the network; an address means that interface only. Overrides and locks the Settings → Network switch.
OH_ALLOW_REMOTE_RELAY off Newer builds: lets other devices use this server's AI relay (the fallback for local AI backends without CORS headers). Off means the relay answers this machine only, so nobody else on the network can use it as a proxy.
OH_RATE_LIMIT 1200 Newer builds: requests per minute per network client (the local machine is exempt).
OH_ALLOW_CROSS_ORIGIN off Disables the cross-origin write guard. Only needed when the game's pages are served from a different origin than the API (for example a separate web server in front of it). Devices that load the game from this server itself never need it.

Going Offline

Once the map data is downloaded, the server, the map, the scenarios, and the editor all run without an internet connection. Playing offline additionally needs an AI that runs offline: a local model through Ollama, LM Studio, or llama.cpp (see the AI setup guide). Without any AI provider the world cannot advance — you can build and edit maps, but not play a turn.

Running as a Service

Linux (systemd)

Create /etc/systemd/system/open-historia.service:

[Unit]
Description=Open Historia Game Server
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/path/to/open-historia
ExecStart=/usr/bin/node server/server.js
Restart=on-failure
Environment=PORT=3000
# Newer builds answer only the local machine unless told otherwise:
Environment=OH_HOST=0.0.0.0

[Install]
WantedBy=multi-user.target

Then enable and start it: sudo systemctl enable --now open-historia

Windows (Task Scheduler)

Create a task that runs node server\server.js in the project directory at startup, with "Run whether user is logged on or not". Set any environment variables in the task's action, or in a small .cmd wrapper.

macOS (launchd)

Create a plist in ~/Library/LaunchAgents/ whose program arguments run node server/server.js with the project directory as the working directory, and load it with launchctl.
